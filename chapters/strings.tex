\chapter{Strings}
\chapterepigraph{A string is an array of characters, so array techniques --
two pointers, frequency counts, prefix sums -- carry straight over. What is
special is the family of pattern-matching algorithms (KMP, Z, Rabin--Karp)
built on one idea: a string's own borders (prefixes that are also
suffixes) let you skip re-comparison. This chapter runs from parsing
puzzles to those linear-time matchers.}

\section{From Character Counting to Border Theory}
\label{sec:strings-intro}

Most easy string problems are careful scanning or counting; the harder ones
are exact pattern matching, where naive comparison is $O(nm)$ and the
prefix/Z functions bring it to $O(n+m)$.

\begin{patternbox}[String Technique Map]
\begin{itemize}
  \item \textbf{Parsing / building strings} -- a single scan with a
        counter or stack: Remove Outermost Parentheses, Maximum Nesting
        Depth, Roman to Integer, Atoi, Count and Say.
  \item \textbf{Two pointers / reversal} -- Reverse Words, Largest Odd
        Number, Longest Common Prefix.
  \item \textbf{Frequency counting / hashing} -- Anagram Check, Isomorphic
        Strings, Sort by Frequency, Sum of Beauty.
  \item \textbf{Expand around centre} -- Longest Palindromic Substring in
        $O(n^2)$ without DP.
  \item \textbf{Border-based matching (prefix/Z function)} -- Rabin--Karp,
        Z-Function, KMP/LPS, Shortest Palindrome, Longest Happy Prefix.
  \end{itemize}
\end{patternbox}

\begin{ideabox}[The One Idea Behind Fast Matching]
A \emph{border} is a proper prefix that is also a suffix. The prefix
function (KMP) and Z-function both compute, in linear time, how much of the
pattern reappears -- so after a mismatch you resume from the longest border
instead of restarting. Every hard problem here is an application of that.
\end{ideabox}
