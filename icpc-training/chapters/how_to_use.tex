\chapter*{How to Use This Book}
\addcontentsline{toc}{chapter}{How to Use This Book}

This book covers the first three topics of the \emph{ICPC Training} tracker
(prep for the ICPC India online preliminary): \textbf{Greedy},
\textbf{Bitwise / XOR} and \textbf{Number Theory}.

\subsection*{Where the problems come from}
\begin{itemize}
  \item \textbf{Notion tracker} (``ICPC Training'' page): every CSES,
        Codeforces and AtCoder problem listed under the three topics.
  \item \textbf{Past ICPC India preliminaries} (the tracker's
        \emph{Historical Prelim Archive}, PDFs from
        \texttt{github.com/m-e-r-l-i-n/icpc-india}): every prelim problem the
        archive files under these three topics. Statements were taken from the
        original contest PDFs, or from CodeChef's archive where the PDF only
        contains an editorial.
  \item Three 2020--21 Amritapuri problems survive only as solution slides;
        their statements are \textbf{reconstructed} and marked with a purple
        box. Their solutions are validated against exhaustive search under the
        reconstructed rules.
\end{itemize}
No problem appears in both lists, so nothing had to be de-duplicated: the
book has 63 distinct problems, ordered from easy to hard inside each
chapter.

\subsection*{Every section has the same shape}
Problem statement $\to$ source and level $\to$ pattern recognition $\to$
approach with the correctness argument $\to$ pseudocode $\to$ a dry run whose
numbers were checked by running the code $\to$ the C++17 solution $\to$ time
and space complexity $\to$ pitfalls.

\subsection*{The code is the tested code}
Every listing is pulled directly from \texttt{icpc-training/<topic>/*.cpp}:
C++17, specific headers (no \texttt{bits/stdc++.h}), fast I/O, small helper
functions. The repository contains
\begin{itemize}
  \item \texttt{tests/run\_tests.py}: compiles every solution with
        \texttt{-Wall -Wextra} and runs all official samples (checkers for
        problems with several valid outputs);
  \item \texttt{tests/stress/*.py}: randomised stress tests against exhaustive
        brute-force references --- tens of thousands of cases, zero mismatches.
\end{itemize}
Passing samples and stress tests is strong evidence, not a judge verdict:
submit to the original judges to be certain.

\subsection*{Suggested order before the prelim}
Easy problems of all three chapters first (they are what decides Q1--Q3),
then the PYQs, then the ``Hard'' tags. Re-read the pitfall boxes the evening
before the contest.
